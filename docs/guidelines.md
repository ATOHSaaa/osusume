# First Books SEO ガイドライン（AI生成コンテンツ向け）

Google の公式ドキュメント（2025年9月版 Search Quality Rater Guidelines、Search Central のスパムポリシー・people-first コンテンツガイド）をもとに、**First Books**（おすすめ小説・漫画ランキングサイト）向けの品質基準をまとめたものです。

記事生成・更新前に必ず参照してください。技術的な品質チェックは [`ARTICLE_GENERATION_CHECKLIST.md`](./ARTICLE_GENERATION_CHECKLIST.md) と併用します。

## 1. Google が明示的にペナルティ対象とするもの

Google は「スパム」と定義される手法を検知すると、**順位の低下**または**検索結果からの除外**（手動対応を含む）を行います。AI 生成コンテンツ特有のリスクは **Scaled Content Abuse（大規模低品質コンテンツ）** です。

### 1-1. スパムポリシー一覧（Search Essentials）

| カテゴリ | 内容 | First Books での典型例 |
|---|---|---|
| **Scaled content abuse** | ユーザーにとって価値のない大量ページを、主に検索順位操作のために生成する | 作家名・ジャンル名だけ差し替えたテンプレ記事を量産する |
| **Scraping** | 他サイトの内容をそのまま／微修正で転載 | 参照記事の本文を要約転載するだけで独自分析がない |
| **Thin affiliation** | 商品説明・レビューを元の販売元からコピーし、付加価値がないアフィリエイトページ | Amazon 商品説明のコピペだけでランキング理由がない |
| **Doorway abuse** | 検索クエリごとに中間ページを量産し、最終的に有用なページへ誘導しない | 似たキーワード用の薄いランディングページ群 |
| **Keyword stuffing** | 不自然なキーワードの羅列 | 「おすすめ 小説 ランキング 2026 ベスト10」を不自然に繰り返す |
| **Cloaking** | ユーザーと検索エンジンに異なる内容を見せる | — |
| **Hidden text / links** | 人間には見えないテキスト・リンクで操作 | — |
| **Link spam** | 順位操作目的のリンク購入・交換・自動生成 | PBN への大量リンク |
| **Expired domain abuse** | 失効ドメインを買い、無関係な低品質コンテンツで再利用 | — |
| **Site reputation abuse** | 既存サイトの評判を借りて無関係な第三者コンテンツを載せる | 文学サイトに無関係なカジノ記事を載せる |
| **Misleading functionality** | 存在しない機能・サービスを装う | — |
| **AI + 順位操作** | AI で生成し、**主目的が検索順位の操作** | ChatGPT に「SEO 向けに100記事書いて」とだけ依頼してそのまま公開 |

### 1-2. Search Quality Rater Guidelines が Lowest（最低品質）と評価するもの

品質評価者ガイドラインでは、以下は **Lowest 評価**（= Google が避けたい結果）に該当します。

- **努力・独自性・付加価値がほぼない MC（メインコンテンツ）**
  - コピー、言い換え、埋め込み、AI 生成を含むが、ユーザーへの新しい価値がない
- **Scaled content abuse の典型**
  - 生成 AI で大量ページを作り、編集・キュレーションなし
  - 複数サイトに分散してスケールを隠す
  - 読者には意味が通らないがキーワードだけ含むページ
- **欺瞞的な目的**
  - ページの真の目的や責任者を隠す（例: 実験用 AI 記事なのに一般向け parenting 記事を装う）
- **事実誤認・信頼性の欠如**
  - 明らかな事実誤り、検証不能な主張（YMYL ほど厳しい）
- **YMYL ページで責任者情報が皆無**
  - 健康・金融・選挙など高リスクトピックで著者・運営者が不明

### 1-3. First Books が特に注意すべきリスク

当サイトは **Amazon アソシエイトリンク** を含むランキング記事を大量に持つ構造です。Google はアフィリエイト自体を禁止しませんが、以下は **Thin affiliation / Scaled content abuse** と見なされやすいです。

- 参照記事の言及回数を集計するだけで、**なぜその順位なのか**の説明がない
- 作家・ジャンルごとに本文がほぼ同一テンプレート
- 出典リンクはあるが、**独自の選定基準・分析・編集判断**が読み取れない
- 受賞歴・作品情報に **事実誤り** がある（文学賞ページは正確性が信頼に直結）

## 2. Google が定義する「人間にとって有用な people-first コンテンツ」

Google の定義: **主に人のために作られ、検索順位の操作が主目的ではないコンテンツ**。

### 2-1. people-first の判断基準（公式セルフチェック）

以下に **Yes** と答えられることが people-first の目安です。

- 既存または想定している読者が、**直接サイトに来ても**コンテンツを役立つと感じるか
- **一次体験**や深い知識が明確に示されているか（実際に読んだ・調査した等）
- サイトに **明確な主目的・焦点** があるか
- 読後、読者が **目的達成に十分な情報** を得たと感じるか
- 読者が **満足した体験** をしたと感じるか

### 2-2. search engine-first の警告サイン（避けるべき）

- 主目的が検索流入の獲得
- 話題を広げて量産し、当たり記事を探す
- **広範な自動化**で多トピックのコンテンツを量産
- 他サイトの要約だけで付加価値がない
- トレンドだけを追い、既存読者には不要な話題
- 読後に「他のサイトを探さないとダメ」と感じさせる
- 文字数目的の水増し
- 専門性なしにニッチだけ狙う
- 未確定情報を確定のように書く
- 中身を変えず日付だけ更新

### 2-3. First Books における people-first の具体像

| 要素 | search engine-first（NG） | people-first（OK） |
|---|---|---|
| ランキング根拠 | 「言及が多かったから1位」だけ | なぜその作品がリストに入るか、どんな読者に向くかを説明 |
| 独自性 | 他サイトと同じ10作品リスト | 言及頻度という**独自の集計方法**を明示し、出典を公開 |
| 読者価値 | タイトルと Amazon リンクだけ | 受賞歴・代表作の関係、ジャンルの特徴など文脈を補足 |
| 更新 | 日付だけ新しく見せる | 参照記事セットや順位根拠が変わったときに実質更新 |
| AI の使い方 | 本文を AI が一括生成してそのまま公開 | データ収集・下書きに AI を使い、**事実確認と編集判断**を人が行う |

### 2-4. コンテンツ品質の公式チェック項目（抜粋）

公開前に以下を自問してください（[公式ページ](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) より）。

**コンテンツと品質**

- 独自の情報・分析・調査があるか
- トピックの包括的・実用的な説明があるか
- 自明でない洞察があるか
- ソースを丸写しせず、付加価値と独自性があるか
- タイトルは正確で誇張していないか
- ブックマーク・共有したくなるか
- 他の検索結果と比べて価値があるか
- 誤字・体裁・作り込みに問題がないか

**専門性**

- 出典・根拠・著者背景が信頼できるか
- 専門家・愛好家による執筆・レビューか
- 事実誤りがすぐ検証できるか

## 3. E-E-A-T の意味と Web ページでの出し方

E-E-A-T = **Experience（経験）・Expertise（専門性）・Authoritativeness（権威性）・Trustworthiness（信頼性）**。

> **Trust が最重要。** E-E-A-T 自体は単独のランキング要因ではないが、Google の自動システムはこれらのシグナルを参考に helpful なコンテンツを優先する。

### 3-1. 各要素の定義と First Books での実装

#### Experience（経験）

| 定義 | 一次体験・生活体験に基づく信頼性 |
|---|---|
| 評価の問い | 「この人は実際にそのトピックを経験したか？」 |
| Web での出し方 | 運営者が実際に読んだ作品への言及、選書理由、サイト運営方針の説明 |
| First Books 例 | About ページで「参照記事を人手で確認し、ランキング基準を公開している」旨を記載 |

#### Expertise（専門性）

| 定義 | トピックに必要な知識・技能 |
|---|---|
| 評価の問い | 「この人はこの分野の知識があるか？」 |
| Web での出し方 | 文学賞の正確な記述、作品・著者情報のファクトチェック、参考文献 |
| First Books 例 | 芥川賞・直木賞などの受賞年・作品名を一次ソース（公式・Wiki 等）で照合 |

#### Authoritativeness（権威性）

| 定義 | そのトピックの go-to ソースとして知られている度合い |
|---|---|
| 評価の問い | 「このサイト／著者は、この分野で参照される存在か？」 |
| Web での出し方 | 被リンク、メディア掲載、分野内での引用、一貫したテーマ特化 |
| First Books 例 | 文学賞・作家別ランキングに特化し、受賞作データベースとして参照される |

#### Trustworthiness（信頼性）★最重要

| 定義 | 正確・誠実・安全・信頼できるページか |
|---|---|
| 評価の問い | 「この情報を信じても安全か？」 |
| Web での出し方 | 免責事項、Amazon アソシエイト表記、連絡先、プライバシーポリシー、出典明示 |
| First Books 例 | `/about/`・`/privacy/`・`/contact/` の整備、記事末尾の参照リンク一覧 |

### 3-2. E-E-A-T 評価の3つの情報源（公式）

1. **サイト／制作者が自分について述べていること** → About、運営方針
2. **第三者が述べていること** → 外部レビュー、被引用、評判
3. **ページ上に見えること** → 本文の正確性、コメント、実際の機能

### 3-3. Who / How / Why フレームワーク（AI 利用時必須）

Google が AI 生成コンテンツ向けに追加した評価軸です。

| 軸 | 問い | First Books での対応 |
|---|---|---|
| **Who** | 誰が作ったか明確か | サイト運営者・編集方針を About に記載。必要なら記事に編集者名 |
| **How** | どう作ったか分かるか | 「Web 記事の言及回数を集計」「Amazon API で商品確認」等の方法を明記 |
| **Why** | なぜ作ったか | 読者の選書を助けるため（検索流入のためではない） |

**Why が最重要:**

- ✅ 読者が直接来ても役立つ → 報われる方向
- ❌ 主目的が検索流入 → 報われない方向
- ❌ AI で順位操作が主目的 → **スパムポリシー違反**

### 3-4. YMYL（Your Money or Your Life）との関係

健康・金融・安全・社会福祉に影響するトピックは E-E-A-T の要求が高い。2025年版では **Government, Civics & Society** が YMYL に追加。

First Books の文学・エンタメ記事は **明確な YMYL ではない** が、以下は高い正確性が必要:

- 文学賞の受賞者・年・作品名（事実情報）
- 著者の経歴・デビュー作
- 児童向け／成人向けの区分（`/about/` の方針と整合）

## 4. 公開前チェックリスト

記事を公開・再生成する前に、以下をすべて確認してください。

### 4-1. 目的とポリシー（Must）

- [ ] この記事の **Why** は「読者の選書の助け」であり、検索順位操作が主目的ではない
- [ ] Scaled content abuse に該当しない（テンプレだけの差し替え量産ではない）
- [ ] 他サイトの要約コピーではなく、**独自の集計・選定・説明**がある
- [ ] 事実（受賞年、作品名、著者名）に **誤りがない**（可能なら一次ソースで確認）

### 4-2. Who / How / Why（Must）

- [ ] 誰が／何がコンテンツの責任主体か、サイト内から辿れる（About 等）
- [ ] 記事の **作成方法**（言及回数集計、Amazon 照合等）が読者に説明されている
- [ ] AI を使った場合、**自動生成部分と人の編集・確認**の範囲が把握・記録されている
- [ ] AI を著者名（byline）にしない（Google 推奨: 人間の責任主体を明示）

### 4-3. E-E-A-T（Should）

- [ ] **Trust**: 免責・Amazon 表記・出典リンクがある
- [ ] **Experience**: なぜこの順位・選定かの説明がある（数字だけで終わらない）
- [ ] **Expertise**: 文学賞・ジャンルの文脈が正確
- [ ] **Authoritativeness**: サイト全体のテーマ（文学・漫画ランキング）と整合

### 4-4. コンテンツ品質（Should）

- [ ] タイトルは正確で、クリックベイト的な誇張がない
- [ ] 読後に「他を探す必要がある」と感じさせない情報量
- [ ] 誤字・変換ミス・不自然な AI 文がない
- [ ] 他の類似記事と比べて **情報ゲイン**（新しい価値）がある
- [ ] 日付を変えただけの偽更新ではない

### 4-5. First Books 固有（Must — 技術チェック）

[`ARTICLE_GENERATION_CHECKLIST.md`](./ARTICLE_GENERATION_CHECKLIST.md) の項目もすべて満たすこと。

- [ ] ランキング 1〜10 件、Amazon 照合済み
- [ ] 漫画・成人向け・雑誌の除外ルールを満たす
- [ ] 対象作家の作品のみ（著者一致確認済み）
- [ ] 参照記事（出典）リンクを記事末尾に掲載
- [ ] Amazon URL は `/dp/{asin}` 形式（検索 URL 不可）

### 4-6. SEO 技術（Should — people-first SEO）

people-first コンテンツに対する SEO は問題ない。

- [ ] 一意で説明的な `<title>` / meta description
- [ ] 見出し構造（h1 → h2）が論理的
- [ ] 内部リンクで関連記事（同作家・同ジャンル・賞）へ誘導
- [ ] 構造化データ（JSON-LD）がページ内容と一致
- [ ] Core Web Vitals / モバイル表示に問題がない

## 5. AI 生成ワークフロー推奨

First Books の記事生成パイプライン（`scripts/generate-article.ts` 等）を使う場合の推奨フロー:

```
1. データ収集（検索・Amazon API・文学賞 DB）  ← 自動化 OK
2. 下書き生成（AI アシスト可）               ← 事実は未確定のまま公開しない
3. 人によるファクトチェック                   ← 受賞年・著者・ASIN
4. 独自要素の追加                             ← 選定理由・読者向け解説
5. 本ガイドライン + ARTICLE_GENERATION_CHECKLIST で最終確認
6. 公開
```

**覚えておくこと:**

- AI 利用自体は禁止されていない
- **順位操作が主目的の AI 量産**はスパム
- AI は特別扱いされない。**中身が helpful かどうか**だけが重要
- 適切な **Who / How / Why** の開示が信頼性を高める
